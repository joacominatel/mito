# 0008 — GRDB for SQLite, pinned exactly

- **Status**: accepted
- **Date**: 2026-10-21
- **Extends**: [0002](0002-project-and-build-configuration.md), [0007](0007-parallel-ready-structure.md)

## Context

`MitoStore` opens the read-only stats snapshot (§17) and, from Phase 8, a read-write personal
database with migrations. `MITO_CONTEXT.md` §7 already names GRDB.swift for both. Raw
`SQLite3` would mean hand-writing statement lifetimes, row decoding, a migrator, and
concurrent access, all of which GRDB provides and tests. It is the only third-party Swift
dependency in MitoKit.

SwiftPM resolves the dependency twice: `swift test` uses `MitoKit/Package.resolved`, and
`xcodebuild` resolves the local package again into the Xcode workspace's own
`Package.resolved`. A range requirement lets the two drift to different versions.

## Decision

- GRDB is a dependency of the `MitoStore` target only, through the `GRDB` product of
  `https://github.com/groue/GRDB.swift.git`. No other module imports it
  (`ArchitectureTests` enforces the per-module import allowlist).
- `Package.swift` pins it with `exact:` (7.11.1, the latest stable release on 2026-10-21),
  so both resolution roots get the same version even without a committed workspace pin.
- An upgrade is a deliberate change to `Package.swift` and `Package.resolved`, a shared
  critical file, checked against GRDB's release notes, with the full validation run.

## Consequences

- No silent upgrades: a new GRDB release changes nothing until someone bumps the pin.
- The pin has to be bumped by hand; nothing warns when it falls behind.
- MitoCore stays dependency-free: snapshot rows reach the engine as MitoCore value types
  through `StatsProvider`, never as GRDB records.
